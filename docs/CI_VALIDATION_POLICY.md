# CI 分级验证操作说明

2026-10-22 校订。目标是减少重复等待，保留业务代码发布的全量验证。

## 什么情况走轻量检查

仅限 main push，且本次全部文件都属于以下 Markdown 白名单：

- 根目录 `README.md`。
- `docs/ledger/` 下的 `.md` 文件。
- `docs/audit/` 下的 `.md` 文件。

还必须验证完整的 before/after 提交、祖先关系和文件差异，并确认 before SHA 的 WMS CI 与 WMS AI Verification 最近运行都为 `completed/success`。查询失败、基线未完成或失败时，不复用旧绿，改跑全量。连续文档提交也必须逐次验证紧邻基线，不能越过一个未验证的代码提交。

轻量分支仍运行文档、月度台账及库存文档定位契约、严格 AI 台账一致性、规则及 gitleaks 凭据泄漏检查，并由聚合任务确认全部必需检查成功。工作流不会因为路径过滤而整体消失。

## 什么情况仍全量

任何业务代码、静态资源、模板、测试、依赖、脚本、工作流、`AGENTS.md`、`DEVELOPMENT_RULES.md` 或白名单外文件变化，都跑原全量 CI。定时、手动触发、PR 和未知事件也全量。无法确认变更范围时默认全量。

本地先跑受影响模块的修改前基线，再做回归锁、字节备份回退验证和模块全量/相邻回归；代码提交的全站测试交 CI 执行，避免本地和 CI 对同一批重复跑全站。不得以效率为由删除或放宽原业务断言。

## SHA 门禁与等待

```powershell
python scripts/check_ci_green.py
python scripts/check_ci_green.py --target-sha <完整40位提交SHA> --json
```

无参数时核实实时远端 main；pre-push 校验远端当前基线，不能要求本地未推送代码已经有 CI。发布前则核验准备部署的目标提交，WMS CI / AI 最近运行须与目标 SHA 一致且成功。

Android 沿用已有路径触发：复用旧构建时须确认成功构建是目标祖先，Git 对象齐全，`app/android-native-wms/` 和 `.github/workflows/android-build.yml` 没有变化；缺证据不放行。每天定时全量保留。性能工作流仍是告警观测，不转为业务发布硬门禁。

CI 排队或运行中允许只读复核、拆分任务、设计用例；禁止提交、推送和发布新 action。实际失败时先修复，认证/403/网络错误仅表示未核实，不等于工作流失败，也不能当作已通过。连接器替代证据须记录 SHA、运行链接和状态，并按 AGENTS 既有程序执行，不能使用无证据跳过。

生产与开发仍共享 `C:\wms`，因此本次不放开“上一批待发布时写下一批代码”。要开放这种并行，先把生产部署固定到独立且已验证的版本目录。本项不改 WMS 业务功能或生产服务。
