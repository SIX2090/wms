# 业务初始化与恢复

2026-10-30，BUG-2026-10-30-002。初始化用于明确决定重新开账的维护窗口，会清空所选业务数据；日常纠错应使用对应单据的反提交和修改流程。

## 上线后的默认行为

网页初始化默认关闭，执行接口返回 403。只有维护人员在 WMS 服务进程的启动环境明确设置 `WMS_ALLOW_BUSINESS_INIT=1` 后，管理员才可使用向导。该开关不应长期配置；维护完成后移除并沿实际托管入口重启。是否同时清理主数据默认不勾选。账号和密码始终保留。

这不是 `WMS_NO_DB_TOUCH` 的用途：后者仅控制启动升级，不是运行期初始化权限开关。

## 执行保护

向导生成有效期 5 分钟的签名预览凭证，绑定数据库、管理员、主数据选项及受影响行的内容指纹。修改、新增、删除或同条数替换都会使旧预览失效。执行时先取得 SQLite 写锁，再核对指纹；从核对到提交期间阻止其他连接写入。凭证使用一次后禁止重放；前端任何执行失败后均须重新打开向导确认。

删除前，服务将完整数据库备份到 `WMS_BACKUP_DIR/initialization/before_init_<凭证编号>.db`；未配置备份目录时沿用独立备份根目录 `C:\wms_backups`。必须通过 SQLite 完整性检查并能读取业务操作日志和审计表，否则禁止删除。备份包含即将清理的业务日志与历史审计，不依赖当前工作目录的导出路径。初始化不会自动清理这些备份；其中含账号及配置，须按业务数据库同等级保管。

库存归零、单据清理、默认参数恢复及本次审计统一提交；任一阶段失败则整体回滚。历史 OperationAudit 保留，本次完成审计记录备份路径。非 SQLite 数据库拒绝网页初始化。

## 若上线后发现误初始化

1. 立即停止继续录单，记录发生时间、初始化完成审计和返回的备份路径；维护人员沿现场核实的实际托管入口停止写入服务，并保留当前数据库、WAL、SHM及日志。不要在运行中冷拷贝或覆盖数据库。
2. 先把初始化前备份恢复到一个全新、明确指定的隔离目标，检查完整性、单据、各仓库库存、流水及账号。示例（两个路径都必须替换为核实过的绝对路径）：

   ```powershell
   python scripts/restore_backup.py "<初始化前备份绝对路径>" --db "<全新隔离目标绝对路径>" --yes
   ```

3. 对比误初始化后是否有新增业务。有新增业务时须保留并逐项核对，不能直接覆盖丢掉这些记录。确认恢复目标、回退资料及业务范围后，才由授权维护人员对已停机的实际目标执行恢复；必须显式传 `--db`，不要依赖脚本默认生产路径。
4. 恢复后复核三账和多仓库边界、单据及账号，再按实际部署入口启动唯一服务实例，核对版本与生效状态，关闭初始化维护开关。

此流程不保证修复前丢失的记录可以找回。2026-10-29 隔离副本事件中，旧备份早于新增盘盈测试且审计导出失败；保留原证据，不能把重建样本称为原记录恢复。本次没有对生产库执行恢复或重启。
