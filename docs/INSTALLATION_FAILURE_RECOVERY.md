# 安装失败时的数据保留（2026-10-17）

适用于 `install.bat` 和 `install_e_wms.bat`。这是失败保护说明，不表示已在生产机执行安装或恢复。

安装失败会停止后续步骤并返回非零，保留安装目录、已有数据库、上传文件、备份、日志和桌面快捷方式。不会删除整个目录，也不会显示“已经完整回滚”。已经复制的程序文件或安装过的 Python 依赖可能仍然保留，需要按安装日志修复。

覆盖前会将现有 `config.py` 留在 `backups/before_offline_install_*_config.py`，用于核对和人工迁移自定义配置。它不是整套旧程序或运行环境的完整备份。数据库会先只读检查，再通过 SQLite 在线备份 API 生成 `before_offline_install_*_inventory.db`，包含已提交的 WAL 数据；备份失败则不继续覆盖程序。

复制程序时排除 `instance`、`backups`、`logs`、`uploads`，以及数据库、环境配置、密钥和运行标记文件。安装包带来的同名文件不会覆盖这些本地数据。已有业务库只读校验后跳过初始化；损坏、不完整或不是 WMS 的数据库会保留并报错，不会自动重置成空库。首次安装没有库文件时才执行初始化。

覆盖已有数据库需要完整安装来源，包含 `scripts/restore_backup.py`、`scripts/online_backup.py` 和相应应用文件。缺少工具时会拒绝继续；不能把便携运行包直接当成覆盖安装来源。

失败后先保留目录和安装日志，确认程序、依赖及配置的修复方案。不要为了“清理失败安装”删除业务目录或已有快捷方式。本流程不自动恢复数据库，不修改已有账号密码；数据库恢复仍需另行确认停机，并按已有离线恢复流程验证和操作。

安装标记只有在写入成功后才会报告完成。文件写入失败也会返回非零，不能仅凭程序文件已复制或桌面快捷方式存在判断安装成功。
