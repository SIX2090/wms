# 库存与数量显示

2026-10-30 · BUG-2026-10-30-004

库存和数量的显示出口不直接输出二进制浮点值。例如`1.2 - 0.3 - 0.5`产生的`0.3999999999999999`应显示为`0.4`，`0.1 + 0.2`显示为`0.3`；整数不强补小数，零附近的四位舍入结果显示为`0`。

`utils.format_quantity`是只读显示函数，使用十进制ROUND_HALF_UP，最多保留四位小数并去掉末尾零，兼容现有期初数量录入步长`0.0001`。空值或无效/非有限值显示空白。Jinja通过`quantity`过滤器使用；物料查询和合并预览仍返回数值类型，标签数据仍保留原字符串类型。Excel浏览器预览的General格式收敛到15位有效数字；显式数字、货币及日期格式沿用原规则。

范围包含物料档案、库存预警、库存查询阈值、手机物料详情、相关AI库存/补货页面、原来直接输出数量的单据/销售页面，以及物料查询、标签批量/入库/预览/打印队列与只读合并预览。同类已有`toFixed`、数字格式化或仓库库存标准化的入口继续沿用现有实现。输入控件、数量校验、库存比较、记账、流水和仓库归属不使用该显示函数；金额和单价不套用数量格式。未修改生产数据库存量数值，也不批量重算库存。

修改Jinja模板后生产需重启WMS服务生效。查看页面不会修正数据库里的浮点表示；业务判断继续使用既有`normalize_stock_quantity`等规则。回归用隔离数据库验证零、正负数、四位数量、同编码跨仓、历史空仓记录、JSON数值类型、标签字符串和页面GET零写入。

同批BUG-2026-10-30-005修复实际足额出库：总账、仓库流水聚合和库位账的条件UPDATE只容忍既有1e-6精度阈值内的浮点尾差，并把该范围内的扣减残差归零。真实差额0.0001仍拒绝，四位有效余量保留；负库存开关和原子并发保护保持。不是仅将页面改为0.4，也不批量修改存量账务。领料单失败会整单回滚，重复完成不能二次扣减。


2026-11-01 · BUG-2026-11-01-031：入库、出库、共用调拨/盘点/BOM/工单领料及调整单的两位小数输入，在键入过程中保留完整原值，离开输入框或收集保存明细时才按现有后端ROUND_HALF_UP规则舍入。发生数值变化时显示原值与结果，例如0.015→0.02、0.005→0.01、1.005→1.01；同一截断逻辑的单价框一起统一。小于0.005的正数量舍入为零时仍提示变化，并由该单据原有的正数/盘点零值规则决定能否保存。保留入库整数不补零和盘点未计数语义；只读系统库存基准不套用输入舍入。粘贴导入和批量修改的“最多两位、超精度拒绝”约定保持。未扩大为全系统四位录入，未批量重算历史单据或库存。生产需重启WMS服务生效。
