# 旧数据库的显式结构升级

2026-11-04，BUG-2026-11-04-105。

`WMS_NO_DB_TOUCH=1` 继续禁止启动期迁移、默认资料与兼容维护。服务启动仍执行只读结构检查：缺表、缺列或类型不兼容时拒绝启动并列出差异，避免用户进入页面后才遇到 500。离线启动脚本不再隐式运行旧的 `fix_db_columns.py`。`WMS_SCHEMA_CHECK=off` 仍仅供明确的临时排障，不能作为正常升级步骤。

升级工具不导入 Flask 应用，只加载模型元数据。默认预览，不改数据库；执行必须显式传入数据库绝对路径、`--apply` 和一个尚不存在的备份路径。它复用 WMS 运行锁，运行中的对应数据库不能升级。备份使用 SQLite backup API，并通过完整性检查。

先在隔离副本预演并核对数据，再安排该数据库的停服维护。以下为路径示例，不能不经核对直接套用到生产：

```powershell
python scripts/upgrade_schema.py --db C:/review/inventory-copy.db
python scripts/upgrade_schema.py --db C:/review/inventory-copy.db --apply --backup C:/review/before-schema-upgrade.db
python scripts/upgrade_schema.py --db C:/review/inventory-copy.db
```

最后一次预览应无待执行语句和阻断项。随后按原部署入口启动；全面结构检查通过后才提供 HTTP 服务。生产执行升级、停服、恢复、重启仍须对应授权；本批只在合成数据库验证。

## 边界

- 仅补模型中缺失的表和列，并补这些新增列涉及的索引、唯一约束。全部 DDL 在一个事务中提交，异常整体回滚。
- 不删除、改名、重建既有表，不更新原有字段，不建管理员或默认仓库，不做库存回填，不生成密码或令牌。
- 新增列采用模型中的固定默认值；可空列无固定默认值时为 NULL。缺少有数据表的非空字段且无固定默认值时拒绝执行，不能猜测历史业务值。
- 历史 77 项函数覆盖缺口已纳入模型驱动的结构测试，不再依赖逐个增加启动 ensure 函数。这个数字不是生产实际缺列数。有存量数据且缺少 `material_category.code`、`supplier.code` 或 `unit.code` 等非空编码时，需要明确编码映射的专项迁移，通用工具会阻断；不能据空表结构测试宣称这些历史业务值已自动恢复。
- 既有字段类型变化、主键、历史数据错误、旧表约束重建不在本工具范围。最终启动检查仍会拦截类型不一致。既有库缺少外键沿用原检查的告警口径。
- 应用失败后保留备份并排查，禁止盲目关闭检查。需要恢复时沿用 `scripts/restore_backup.py` 的独占锁和恢复流程。
