# 一键更新操作说明（2026-10-17）

本入口适用于含 `.git` 的 Windows 源码部署；仅复制的便携包没有 Git 仓库时不能使用。双击仓库根目录的 `update_from_github.bat`。更新器只操作当前仓库的 `main` 分支；本地有未提交文件时会拒绝覆盖，请先保留并处理这些改动，不要直接删除不认识的文件。

更新按以下顺序进行：

1. 下载远程版本，检查能否快进、现有依赖能否直接使用，并对已有数据库做一致性备份。
2. 确认端口进程属于本目录的 WMS，再停止服务。进程身份不明确时拒绝自动停止。
3. 更新到已下载的固定版本，启动新进程，同时检查新 PID、端口归属和登录页响应。
4. 显示实际结果。启动失败不会显示“更新完成”；停机后失败会尝试回退旧代码并恢复原先运行的服务。

更新器不自动修改共享 Python 依赖。新版本的 `app/requirements.txt` 有变化、缺少依赖、依赖冲突，或 pip 不支持只读预检时，会在停服前拒绝更新。此时需要安排维护窗口单独升级运行环境，不能将失败提示当成更新成功。

更新器必须使用与运行中服务相同的 Python 环境；不一致时拒绝停服。请保留原有配置文件，并从原部署环境运行更新入口，避免更换解释器或遗漏明确配置的启动环境变量。

更新前的数据库备份保存在根目录 `backups`，文件名以 `before_github_update_` 开头。本工具不自动恢复或替换业务数据库，不删除业务目录；`app/WMS_NO_DB_TOUCH.flag` 会保留，避免更新时自动迁移数据库。

代码回退使用 `git reset --keep`，不会使用强制清理。若更新期间有人修改代码、切换版本，或旧服务恢复失败，工具会返回非零并明确提示人工处理，保留现有文件。即使旧版本已成功恢复，这次更新仍然报告失败，需处理原因后重试。原先没有运行服务时，失败回退不会自行启动旧版本。

旧实例若只用相对路径 `run_server.py` 启动，安全检查器不能确认其所属目录，会要求人工确认。确认后使用仓库原有的 `start_wms_offline.bat` 启动入口，新实例会携带完整脚本路径。不要依据“某个 Python 占用 8080”就认定它是本目录 WMS。

自动化环境可使用 `update_from_github.bat --noninteractive` 取消末尾按键等待；退出码 0 表示更新成功或没有新版本，非零表示未完成，具体恢复状态见输出。不要对生产目录运行故障注入测试。

当前操作流程针对普通进程部署。由 NSSM/Windows 服务托管时，需要维护人员统一管理服务的停止和恢复，不能只结束 Python 子进程；服务托管协同另按启动入口专项核查，不在生产试运行未知启停流程。
