# 网页新建单据重试保护

2026-11-03，BUG-2026-11-03-101。

网页保存新单时，服务器可能已保存，但浏览器没有收到响应。原页面再次保存现在返回首次成功的单据和结果，避免同一次请求重复建单。

## 使用与接口约定

- 统一 `WMS.api` 请求层为下列新建入口发送 `X-Idempotency-Key`。请求标识为页面内随机值；同一页面、同一预览单号的重试保持该值。重新打开新建页使用新标识，避免删除后复用预览单号误命中旧凭证。无单号时保留当前页面的请求标识，直到收到成功响应。
- 同一账号、同一入口、同一请求标识和内容重试，返回首次成功的完整 JSON，包括单据 ID、正式单号及原有提示。CSRF 令牌不计入业务内容指纹。
- 同一标识已成功保存其他内容时返回 HTTP 409。请先打开原单据核对，再按单据 ID 编辑；不要把请求号冲突理解为修改已生效。
- 临时获取写锁失败返回 HTTP 503，可保留页面稍后重试。校验失败或事务失败不会留下成功凭证，可以纠正内容后重试。
- 带有效 `id` / `order_id` / `request_id` 的编辑仍走原有编辑流程。未携带请求标识的旧调用方保持兼容，但不能获得这项重试保护。调用方主动重新发起新建意图时应使用新标识。
- 该机制按请求意图区分，不按内容强制去重；“疑似重复单据”提醒、权限及 CSRF 校验仍保留。批量导入、AI 生成、下推与完成/反提交不属于本次接口变更。

## 覆盖入口

| 单据 | 新建保存地址 |
| --- | --- |
| 入库（采购、产品、其他、销售退货） | `/in_order/add` |
| 出库（销售、领料、其他、采购退货） | `/out_order/add` |
| 调整、售后出库 | `/adjustment/add`、`/after_sale_out/add` |
| 盘点 | `/check/save_table`、`/check/add` |
| 调拨 | `/transfer/save_table`、`/transfer/add` |
| 请购、采购订单、销售订单 | `/purchase_request/add`、`/purchase_order/save`、`/sales/add` |
| 工单领料 | `/requisition/save_table`、`/requisition/add` |
| 委外订单、发料、收料 | `/subcontract/add`、`/subcontract_issue/add`、`/subcontract_receive/add`；发/收料兼容别名 `/subcontract/issue/add`、`/subcontract/receive/add` |

## 存储与生效

使用已有 `mobile_api_request` 表，网页入口使用独立 `web:` 命名空间。唯一约束按账号、入口、请求标识串行化并发重试，业务单据与成功响应在同一事务中提交或回滚；不新增表或启动迁移。登录和原有角色检查在重放前执行。

本次为代码交付，生产部署及重启另行执行。部署后需重启 WMS 服务并刷新网页加载请求层。未自动部署、重启或修改生产单据、库存及凭据。
