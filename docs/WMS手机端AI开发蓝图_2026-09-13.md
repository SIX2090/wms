# WMS 手机端 AI 开发蓝图

> 编制：仓储老陈（WMS/MES 数字化顾问）　｜　日期：2026-09-13　｜　代码基线：main `1522c2a`
> 企业背景：低压成套设备生产，1–2 仓 / SKU<2000 / 日均<50 单，开发与试行阶段
> 技术栈：后端 Flask + SQLite（Waitress），手机端 Kotlin + Jetpack Compose，LLM 走 OpenAI 兼容协议
> 编写方法：全部结论基于代码实证（文件:行号），未实读的功能不写入本蓝图

## 〇、一句话结论

**手机端缺的不是 AI 能力，是"没接上电脑端已经建好的 AI 大脑"。**

后端 `app/ai/` 已经有一套完整的助手体系（意图解析、知识库、工具调用、多轮会话、反馈闭环、预算控制），而手机端目前只调了其中 3 个端点（OCR 识单、识物、语音开单），**对话、会话、反馈三大件一个都没接**。本蓝图的核心策略是：**手机端做"嘴和耳朵"，大脑复用，不为手机重建一套 AI**。

### 1.3 差距定位

```
电脑端助手：  问答框 ──→ chat_stream ──→ 意图/知识/工具/会话/反馈  ✅ 全通

              问答框 ──→ ✗ 不存在      ←—— 缺口在这里
              反馈   ──→ ✗ 未接入
```

## 二、目标架构

```
手机端（嘴和耳朵）
  麦克风 FAB（已有）──┐
  问答输入框（新增）──┼──→  POST /api/mobile/ai/chat（新增，复用后端大脑）
  相机（已有）───────┘            │
                                  ▼
后端 AI 大脑（复用，不重建）
  ① 文本归一化 + ASR 纠错（已有 correct_voice_asr_text）
  ② 意图 Router（复用 call_llm_intent，新增手机端 system_prompt）
        ├─ 开单意图 → voice_out_draft / inbound_draft（已有，保持草稿边界）
        ├─ 查询意图 → tools/inventory.py（已有，实时查数，禁背答案）
        ├─ 指引意图 → knowledge.py（已有，规则 + 页面入口 → deep link）
        ├─ 异常意图 → 操作 SOP + 转人工指引（新增知识条目）
        └─ 不明     → 明说"我不确定"，给文字搜索入口（R5 铁律）
  ③ 答案组装：一句话结论 + 数据卡片 + 跳转动作
  ④ 反馈：feedback_create（已有，手机端接一个 👍/👎）
  ⑤ 日志：ai_run / message 全量落库，未命中问题每周回流
```

**三条架构铁律（与 AGENTS.md 对齐）：**
1. **AI 只生成草稿和答案，绝不直接写业务数据**（提交/完成永远人工）。
2. **数据类问题必须实时查库**（库存、单据、数量），LLM 只负责理解问题与组织语言——这条知识库已内置，手机端继承。
3. **答不了就说不确定**，禁止编造（R5）；所有 AI 端点注册进 `AI_PERMISSION_MATRIX.md`。

## 三、意图体系（手机端五类，分期开放）

| 意图 | 示例 | 开放期 | 风险 | 复用资产 |
|---|---|---|---|---|
| **开单** | "领 8*25 螺丝 1000 个" | 已有 | 中（有草稿确认兜底） | voice_out_draft 六层匹配 |
| **查询** | "6204 轴承还有多少""M8 螺母在哪个库位" | **一期** | 低（只读） | tools/inventory.py |
| **指引** | "调拨怎么反提交""盘点中途退出怎么办" | 二期 | 低（知识库答案+跳页面） | knowledge.py |
| **异常** | "提交了但没反应""扫不出来这个码" | 二期 | 中（需准确 SOP，错误指引有害） | 新增知识条目 |
| **faq/闲聊** | "你能干什么" | 二期 | 低 | 固定话术，不接 LLM 也可 |

**一期为什么只开"查询"**：只读、答错不出事故、最能验证识别率与意图准确率。这是我在真实项目里的做法——**先拿只读意图把链路跑顺，再开放有副作用的意图**。

## 四、分期路线图

### 一期：接通大脑（预估 5–8 人天，经验估算非实测）

| 工作项 | 内容 | 验收标准 |
|---|---|---|
| 后端新增 `POST /api/mobile/ai/chat` | 薄封装：鉴权 → 意图分类 → 查询工具 → 组装卡片答案；复用 conversation 体系 | 手机端问"XX 还有多少"返回实时库存卡片 |
| 手机端问答入口 | 首页搜索框 + 麦克风水Long按说话/短按开单（或问答页内语音输入） | 入口两步可达 |
| 答案卡片组件 | 一句话结论 + 数据行 +「去查看」deep link 到查库存页 | 点击跳转携带物料编码 |
| 反馈 👍/👎 | 接 feedback_create | 反馈落库可查 |
| 权限注册 | 新端点登记 AI_PERMISSION_MATRIX + AI 台账任务 ID | 台账/矩阵可查 |

### 二期：会指路（预估 10–15 人天）

- **指引意图**：知识库条目答案 + 页面 deep link（knowledge.py 已有 page_endpoint 字段，手机端映射到 App 路由）
- **异常意图**：整理 10–20 条高频异常 SOP（提交无响应、扫码不识、离线补传失败、打印没出纸）进知识库
- **语音 Router**：麦克风从"只会开单"升级为"先分意图再路由"（开单/查询/指引）
- **未命中回流**：每周导出"判为不明/👎 的问题"，人工补知识条目

### 三期：能看会拍（预估 8–12 人天，视一二期数据再定）

- 拍照异常取证：单据行关联照片（复用 material_archive 图片管道与压缩逻辑，注意 2GB 服务器内存）
- 识物增强：识物结果直接带出库存与库位卡片
- 主动提醒：库存告警/待办推送到手机（后端已有 alert/list 与通知调度器）

### 明确不做（划边界）

- ❌ 需求预测 / 智能补货模型（日均 50 单的数据量喂不出预测，这是数据规律）
- ❌ 自由闲聊（做工具型问答，不做陪聊；闲聊意图固定话术应对）
- ❌ 手机端独立建一套知识库/会话（复用后端，避免两套数据漂移）
- ❌ AI 直接提交/完成任何单据（铁律，永久不做）

## 五、关键接口设计（一期）

```
POST /api/mobile/ai/chat
Request:  { "text": "6204轴承还有多少", "conversation_id": 可选, "channel": "mobile" }
Response: {
  "intent": "query",                    // query|draft|guide|exception|unknown
  "answer": "6204 轴承当前可用 150 套（一号仓 100，二号仓 50）",
  "card": { "type": "stock", "items": [...] },   // 结构化卡片，手机端渲染
  "actions": [{ "label": "去查看", "route": "stock_query", "params": {"code": "6204"} }],
  "message_id": 123,                    // 供反馈回传
  "confidence": 0.92,                   // 低置信时前端提示"可能理解有误"
  "fallback": null                      // unknown 时给文字搜索入口
}
```

- 鉴权复用现有 mobile token；限流复用 budget_control；超时应答 ≤5s（超时给"稍后再试"，不转圈死等）
- **R1 合规**：查库存走仓库级口径（get_warehouse_stock_quantities），默认仓与手机端首页口径一致
- 日志：请求文本、意图、置信度、工具调用、耗时、反馈全部落库（脱敏后）

## 六、验收指标（每期结束实测）

| 指标 | 测量方法 | 目标 |
|---|---|---|
| 意图分类准确率 | 每周抽 50 条日志人工核对 | 一期建基线，二期 ≥90%（行业参考值，非实测） |
| 查询答案数据正确率 | 答案卡片 vs 实时库存抽对 | **100%**（工具查数，不允许错） |
| 平均响应时间 | 日志耗时字段 | ≤5s（经验参考） |
| 👍 率 | feedback 统计 | 一期建基线，逐期提升 |
| 未命中率（unknown 占比） | 日志统计 | 逐期下降，每周回流补知识 |
| 越权/写库事故 | 审计 | **0（红线）** |

> 数值目标为**行业参考值，非实测**；一期结束必须用自己数据重建基线。

## 七、风险与对策

| 风险 | 对策 |
|---|---|
| 车间嘈杂导致 ASR 误识别 | 已有纠错管道；查询类误识别可追问确认（"您是想查 6204 轴承吗？"） |
| LLM 答非所问/编造 | 数据走工具实时查，知识走知识库，LLM 只组织语言；低置信度显式提示 |
| 2C2G 服务器扛不住并发 LLM 调用 | budget_control 限流 + 超时收紧 + 意图分类用短超时（providers 已有 2–6s） |
| 手机端离线 | 离线时助手明确提示"当前离线"，问题本地记录联网后补（复用离线队列机制） |
| 手机端与电脑端答案不一致 | 同一个大脑同一个知识库，天然一致；禁止手机端另写规则文案 |
