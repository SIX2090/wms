## 客户端版本契约

- 普通网页继续读取 `meta[name=document-revision]`，既有统一层发送 `X-WMS-Document-Revision`，表单支持 `document_revision`。保存成功返回下一次编辑使用的版本；冲突后应保留输入，重新打开、核对当前内容后由操作者再保存，禁止透明获取最新版本并盲目重试旧内容。
- 委外发料、收料详情为只读 HTML 片段，GET 响应另含 `X-WMS-Document-Read-Revision`。调用明细编辑时把它作为 `X-WMS-Document-Revision` 传回。读取头与保存头分开，避免现有全局响应处理器把子单版本误装到父单页面。
- 原生期初明细列表 `GET /api/opening_stock?warehouse_id=...` 的每行包含 `revision`；编辑 `POST /api/opening_stock/<line_id>` 在 JSON 中原样传回，同时保留 Bearer 授权和请求重放键。版本绑定账号和行内容，比较与库存差额写入共用 SQLite 写锁/事务；成功结果及下一版本在提交前捕获，避免返回另一操作者提交后的快照。
- 历史 `doc_id` 为空的期初行使用列表返回的行版本，Web 旧行编辑也执行比较。没有自动归单、回填仓库或迁移历史记录；仓库为空的移动明细仍按原规则拒改。
- Android 列表模型、编辑请求与 ViewModel 同步携带版本，失败保留编辑状态。旧 App 没有版本时不能继续覆盖已有期初行，需要配套升级；新建/扫码的既有协议不变。真机安装、触摸和软键盘验收按用户要求保留为硬件待验，不拿源码或编译测试冒充完成。
