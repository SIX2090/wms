## Linux CI 执行边界

入口：`python scripts/run_ci_isolated.py -- python scripts/run_tests_sharded.py`。
其他明确非空命令由相同启动器运行；分片数量、并发方式、失败退出码和聚合门禁保留。

1. 启动器只支持本机 Linux Docker，拒绝远程引擎、非测试数据库环境和未提交源码。
2. 先列出精确 Git 对象的文件名并排除数据库、备份、实例目录、上传、日志、输出及环境文件，
   再读取允许的普通源码 blob。拒绝链接、子模块及越界路径。不会复制现有工作目录或生产数据。
3. 测试容器使用 UID 10001、只读根文件系统、全部 capability 撤销、no-new-privileges、
   独立 PID/网络空间和 `network=none`。唯一宿主挂载是本次新建的只读证明目录；
   状态目录为新建 tmpfs，不挂载 checkout、Docker socket、凭据或生产目录。
4. 启动器先核对实际 `docker inspect`，再向等待中的 PID 1 签发证明。
   证明绑定容器 ID、源码哈希、PID 1 创建时间及内核 namespace。
   子进程重新检查 UID、capability、seccomp、只读挂载、loopback-only 网络及不可写证明。
   环境变量、复制的 JSON、继承的文件库地址均不能单独充当证明。
5. 每次运行先执行真实边界自测，验证新内存库/合成文件库、只读源码、子进程、
   伪造证明、错误数据库和链接拒绝，再执行原测试命令；失败保持非零退出。
6. 只回收本次随机 label 与精确 ID 匹配的容器，不能删除用户其他容器。

Windows 保留现有 LPAC/Job/WFP 验证方式；没有为本机安装 Docker、启用 WSL、重启或修改系统服务。
Linux 容器真实构建和运行必须由目标 SHA 的 CI 验收，本机静态/模拟测试不能代替它。

## 消费点修复

- AI 调度器两种数据库变量均为新内存库，每个子进程仍有独立临时状态；严格台账开关保留。
- `verify_wms_bugs`、启动更新验证和 AI 运维验证先核对运行能力再导入应用；导入失败不能报跳过成功。
- 三账 ORM 读取先验证已加载应用的数据库归属；独立 SQLite 读取仍强制只读。
- 冒烟继续使用持有的监听 socket、私有管道、子进程 PID 与 nonce，逐次核对目标和响应。
- 冒烟身份证明通过现有文件租约读取，解决 LPAC 无权查询宿主盘符映射的问题；
  未改成对生产路径开放权限。POSIX 通过 no-follow/openat 持有文件描述符。
- 浏览器服务绑定端口 0，成功监听后才发布 PID/随机实例身份/高位端口，取消“先取端口再关闭”窗口。
  重定向、来源限制、库存不变、普通保存不完成单据等断言保留。
- 工作流历史 payload 哈希保持原值，只规范化精确隔离启动器前缀，并新增必须使用启动器的断言。
