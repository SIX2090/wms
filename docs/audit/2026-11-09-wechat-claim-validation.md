## 根因及修复范围

旧轮询只查询 pending，不持久领取；两个助手可获得同一任务。图片读取与结果回报也没有绑定具体领取者。直推与轮询可能并发处理同一业务键；清理未保护全部活动状态，可能删除正在处理的图片或同业务键记录。此前的 ready → uncertain 只缓解完成后的重复，不能覆盖领取与响应丢失。

本次复用既有日志和 dispatch 表，不新增 schema 或执行生产迁移：

- 新任务使用 queued_v2；领取通过原子条件更新进入 sending，返回随机领取凭据，日志只保存其 SHA-256。一次只领取一项。请求发起前检查助手协议版本，旧助手返回 426；已有无归属证明的 pending 保留为历史待人工核对，不推断、清空或自动重发。
- 图片要求当前领取凭据，并在提供图片前原子切换到 delivery_started。同一凭据再次读取被拒绝；若响应丢失，保留可能已交付状态，不自动重新排队。助手只访问配置同源的固定任务端点，忽略响应中的任意图片／回报地址，领取、图片和回报均不跟随重定向。
- 回报绑定日志、活动状态和领取摘要，迟到报告返回 409，不覆盖已发送／待确认结果；原始诊断保留。非确定结果附人工核对指引；已粘贴仍为 uncertain，不声称已经由人发送。
- 直推领取在短 SQLite 事务中同时核查轮询状态；打印告警先持久占位再渲染／发送，只有明确尚未发出的配置错误才进入新队列。可能已发生 UI 动作的错误保持 uncertain，保留经过字符及长度限制的错误码，不保存任意响应正文或令牌。
- 清理保护 pending、queued_v2、sending、delivery_started、uncertain 等活动状态及同业务键记录；图片清理在独立短 SQLite 写事务内核对活动图片路径。连接池不能证明独立连接、调用者仍有业务事务或数据库方言不支持时拒绝清理。
- 页面隐藏内部领取摘要、区分历史待核对／待领取／发送中／结果待确认，并阻止活动任务同时直推。生产需重启 WMS 服务生效；本次未重启，也未更新已安装助手。

通知 ID 删除后可能复用，因此告警占位同时核对已记录的标题，避免明确不同通知因相同 ID 永久误挡。若历史 ID 和截断标题均相同、无法证明归属，仍需人工核对，不承诺恢复历史身份或自动解除未知占位。
