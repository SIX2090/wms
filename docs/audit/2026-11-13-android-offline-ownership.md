# Android 离线队列归属整改

对应 BUG-2026-11-08-012。代码基线为 `8e8339403996800d522caa3ec4b6a62367bc97d6`；本任务保留此前首页/日报和并行 CI 规则提交，只处理队列及其身份、持久化和界面消费点。未连接、读取、复制或修改生产数据库、生产备份，未请求现役服务、默认 8080、真实账号或业务单据，未安装 APK、部署或重启。

## 目标与改动

- 新记录绑定原始提交时的完整规范化服务地址与服务端用户 ID，不持久化令牌，不按输入的用户名猜身份。带用户信息、query 或 fragment 的 URL 不可作为队列归属。旧登录缺少可证明的用户 ID 时，不能谎报已安全暂存，应保留页面并重新登录。
- 原请求、出库预检和失败暂存共用一个不可变会话快照；补传按该条原归属重新取 API，发送时沿用 BUG014 的来源和会话代次保护。换账号/服务器不自动改归属；原账号换新令牌可继续。同 requestId 不覆盖 payload、归属、状态和失败信息，冲突或已需人工处理时明确拒绝重新入队。
- Room v1→v2→v3 显式升级，只新增归属、人工核对标志和重试时间；旧 payload、requestId、status、attempt_count、last_error、时间原样保留。无归属旧记录全部标记 needs_review，自动补传、启动复位和人工重试均不可绕过。
- 429 按 Retry-After 秒数/HTTP 日期或有限指数退避延迟，沿用五次尝试上限；401/403 保留为待身份/权限处理；400/409/422 保留明确业务拒绝。非 2xx 的中文原因从真实 errorBody 读取，失败不静默。取消不创建另一条离线请求。
- Room 打开失败保留原库，由仓库层降级；禁用自动删库重建，并覆盖默认 corruption callback 的删库行为，禁止 recovery data loss。历史诊断读取/回补辅助仍保留并保真新增字段，不接入启动恢复。
- 入库、出库、盘点三页共用横幅显示具体原因；无可处理记录的账号不显示无效重试按钮，历史记录明确提示人工核对。切账号后不沿用上一账号的失败详情。登录/冷恢复及网络恢复可触发按归属校验的补传。

Android 版本为 36 / 3.9.12，Windows 发行版本为 2026.11.27；版本递增不代表已安装或生产已生效。

## 升级、回退和生效边界

新版本升级在单一 Room 事务执行；迁移/校验失败由原事务回滚并保留原库，未来 schema 无兼容迁移时拒绝打开，不猜归属或删库。历史旧 APK 自带自动删库恢复代码，无法通过新 APK 修改旧二进制的行为，**不得强制降级到 3.9.11 及更早版本来处理队列故障**。正常安装版本号递增防止普通覆盖降级；需要回退界面/业务代码时，应构建保留 v3 schema、归属隔离和保库保护的兼容回退包，另行验证。私有源码 R8 不等于在设备上安装旧 APK。

真实设备安装/升级、旧 APK 强制降级及现场队列归属确认均未执行；无归属记录仍由人工核对，本批不提供猜账号、批量清空或绕过归属的处理入口。生效确认：待人工确认。

默认损坏回调会删除文件的依据见 [AndroidX SupportSQLiteOpenHelper 源码](https://github.com/androidx/androidx/blob/androidx-main/sqlite/sqlite/src/androidMain/kotlin/androidx/sqlite/db/SupportSQLiteOpenHelper.android.kt)；本批通过自有 factory 阻止该默认回退。
