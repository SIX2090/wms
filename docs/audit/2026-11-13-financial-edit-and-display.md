# BUG-2026-11-08-015：财务历史保存与显示分量

本批以 `5f002fd5ef32107ac678b452f030aef5cc4c6c52` 的本地/远端main为整批回退基线。代码、精确目标CI、生产生效分别验收；本报告记录候选范围及验收依据，不表示已部署。

## 修复与保持的业务

- 采购单与采购申请的仅备注保存此前整删重建行，历史记录金额、数量/价格精度、行身份和上游关联可能丢失。新页面带本单行ID，服务端复用各域实际已有签名版本和事务锁；未改财务分量原位保留。外来、重复、非法行ID、换料复用原行和已收/下游关联仍明确拒绝。旧无ID请求保持原有明确替换，不靠SKU猜旧行。
- 已知金额0与缺失None分别处理；客户端传入saved_amount不能冒充服务器财务快照。已知单头与明细存在历史差异时，仅元数据变动不偷偷重算单头；真实增删或主动改单分量后按原业务汇总。
- 采购申请不强制两位数量/预估价，也不强制每个需求报价。原价NULL但已有非零历史估算额，改数量仍不报价时拒绝猜价清零；零额/缺失估算额的普通未报价需求仍可改量。
- 采购单/销售的新分量或实际改变的分量沿用后端两位规范，未改变的历史分量保留原精度。页面显示按相同分量规则计算，不能把历史1.2345×3.56789统一量化，也不能让新行显示4.40而保存4.39。
- 三域已识别且原价NULL的历史行，复用parse_float_value(value,None)及布尔拒绝验证明确报价。空白经strip视为缺价；非法/非有限/负数/容器不能默默转成0或物料默认价；明确合法0/正价允许。范围没有扩大到所有已有非NULL价格或旧无ID请求的输入政策。
- 采购两种复制、销售编辑复制/加载模板、销售新增输入/复制/模板均按新行既有业务处理，不继承原行ID或历史金额；原历史行不被格式化。主动模板替换继续是替换业务，SQLite可能复用数字PK，验证使用ORM对象身份及实际字段，不要求新PK必不同。
- 销售历史停用物料不在可选缓存时，只能从同code原行携带的material快照取得页面已知默认价，不把停用物料加入可选清单，不猜未知原单价。
