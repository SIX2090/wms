## 根因与范围

销售出库的共享页面/打印数据源和现有 Excel 导出均把 `item.amount == 0` 当作缺失，再按数量与单价重算；两处又把已存税率 0 替换成默认 13%。AI 销售草稿只读检查适配器存在同一零税率替换。读取三处真实源码表达式，用合成的已存金额 0、数量 2、单价 3，输出金额变为 6；零税率变为 .13，共五个错误子案例。

OutOrderItem.amount 为非空、无默认值的已存金额；不应在只读报表中将合法 0 当作缺失。SalesOrderItem.tax_rate 明确允许 0，销售保存、重算和网页输入已保留 0。修复仅在 None 时使用原默认值/金额推算，保留历史 4.02/7.77、普通 13% 和来源缺失时的默认值。没有重算或回写历史单据，没有修改税率、金额、库存或权限的数据模型。

同类点已排查：全仓 Python/JS/模板的非零税率默认、金额乘法回退、网页新增/编辑/粘贴、Excel 税率读取、共享打印、现有 Excel 导出、AI ORM 适配、迁移 COALESCE 和金额消费者。JS 粘贴取得字符串 '0'，本就不触发 `||` 默认；编辑显式判断 null/undefined，保持。销售 tax_included_amount/amount 兼容字段涉及既有迁移补齐约定，不机械替换其历史回退；其他历史重算、数量尾差和报表口径仍属 BUG015 的剩余范围。
