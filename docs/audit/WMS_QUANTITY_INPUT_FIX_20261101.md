# WMS 数量静默截断修复与验证

2026-11-01 · BUG-2026-11-01-031

## 结论与行为

旧页面在每次 input 时截掉第三位小数。0.015和1.005分别变成0.01和1.00，可以保存进草稿；0.005变为零，保存才被有效性校验拦住。不是单纯显示格式，也不是报表独立计算错误。

修复保留后端既有两位 ROUND_HALF_UP 规则：键入过程中不改值，失焦或收集保存明细时再舍入；实际数值改变时提示原值与结果。

| 键入 | 输入期间 | 舍入结果 |
|---|---|---|
| 0.015 | 0.015 | 0.02 |
| 0.005 | 0.005 | 0.01 |
| 1.005 | 1.005 | 1.01 |

小于0.005的正数舍入为零仍有提示，随后沿用原正数/盘点零值规则。正常两位输入不改写，入库整数不补零、盘点未计数/null及系统库存基准保持。后端精度、金额算法、库存记账、权限及历史数据均未修改。生产需重启 WMS 服务生效，本轮未部署或重启生产。

## 修改及同类排查

- 新增 `app/static/js/decimal-input.js`，通过十进制数字格式化处理半位，避免 `toFixed` 的二进制半位偏差；变化时使用既有 showToast。
- 四个模板在页面代码前加载共用脚本：in_order_add、out_order_add、document_table_form、adjustment_add。删除所有同型 substring 小数截断；初始行及插入行均覆盖。
- 同一截断根因的单价输入一起修复，提示标明“单价”；不改变金额计算规则。
- 保存收集阶段也调用规范化，不依赖鼠标点击一定导致 blur；盘点只处理实盘，系统库存基准不舍入。
- 关联历史F4.1后端舍入修复、BUG-2026-09-22-002、BUG-2026-10-21-002及BUG-2026-10-30-004。全仓同型截断只命中这四个模板；粘贴导入/批量修改仍明确拒绝超过两位的小数，保留既有约定。
- 既有运行时测试夹具补加载真实共用脚本，保持原断言；新增回归执行实际页面监听器及 collectItems，而非只比字符串。
