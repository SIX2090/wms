# 微信分享历史清理（2026-11-01）

关联 BUG-2026-11-01-021，基线 `867e369a8bf7227a093374ac185f7bfc186450ab`。

## 操作

管理员打开“微信分享”，在“分享记录”点击“清理历史记录”。默认90天前，也可选择30天前或全部历史记录。“预览清理数量”显示全部匹配记录数，不受列表状态筛选或最近10/20/50条限制。确认前核对数量；图片默认保留，可勾选同时清理关联图片。最后的永久清理确认由操作人决定。

“N天前”按服务端本地日期零点计算，严格早于该日期；预览显示具体截止日期。修改选项、取消确认或执行失败后须重新预览。预览有效期10分钟，绑定当前管理员、范围、图片选项和记录快照；数据或任务状态变化时拒绝使用旧预览。

只清理已发送、失败和跳过的记录。待发送、发送中、结果待确认及相关业务键处于准备/执行中的记录保留。历史未知状态不删除。筛选旁“清除”改为“重置筛选”，仅重置筛选条件。

## 数据边界

- 不操作入库单、库存或微信端消息，不撤回已发送消息。
- `wechat_share_dispatch` 中的防重复发送保护保留；旧成功记录和结果未知的旧失败记录在删除前补存保护标记。同一SQLite写事务序列化清理与领取，已有失败占位也保留旧成功/未知结果的保护，不能因删日志恢复自动投递。
- 旧“清理失败”入口复用相同保护，仍只接受failed/skipped且保留图片。
- 图片在记录事务成功后清理；仅处理被清理记录关联、分享目录内的PNG，排除链接/目录联接、其他记录的引用、活动任务相关文件及目录外文件。不扫描删除其他孤立文件。再次持有SQLite写锁核对引用，文件失败如实汇报，不把记录已删除说成整体未执行。
- 缺少既有`wechat_share_dispatch`表时受控拒绝预览/清理，不自动建表。本功能无数据库模型或迁移变更。
