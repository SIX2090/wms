## 本计划的操作范围

允许只读查询计划任务和进程/端口元数据、读取程序源码和封存程序清单。代码已推送、精确CI已验收、候选制品已封存和生产已生效分别记录。

## 被动身份核对入口

`scripts/health_check.ps1`现在默认仅做被动核对：指定任务Running、唯一监听PID、精确解释器/入口/参数、父链与注册任务动作关联、进程时间防PID复用，以及固定`wms-release.json`的后台/UI来源。缺预期参数、查询失败、归属不明或来源不符均返回非零。它不导入WMS、不打开数据库、不发HTTP、不启停服务；只读程序清单拒绝链接/目录联接/硬链接和超大文件。

示例在PowerShell内执行；把三个路径和完整SHA填为本次核实值。EntryArguments必须与原入口实际参数一致，保留必要的引号；普通入口不带参数时传空字符串。ValidatorPython只执行标准库身份校验器，不启动对应解释器中的WMS。

```powershell
$release = 'C:\wms_releases\20261107_print_layout_6d10e56b'  # 2026-11-07快照，先复核
$source = '6d10e56b251b2d6cc2a672693bc7890e0316e308'
.\scripts\health_check.ps1 -InstallDir $release -Port 8080 -TaskName 'WMS-Warehouse' -ExpectedSourceSha $source -ExpectedPython "$release\python\python.exe" -ExpectedEntry "$release\verified_entry.py" -EntryArguments '--state-root C:\wms --version "current" --serve' -ValidatorPython "$release\python\python.exe"
```

在Windows PowerShell 5.1和7中脚本保留UTF-8 BOM，并明确设置标准输入/输出编码；不要在另一层原生命令行中丢掉EntryArguments内的引号。可选`-IncludeLogMetadata`只取两种既有日志目录中较新的文件元数据，不读取日志内容或任何数据库文件；该信息不参与身份通过判定。

退出0表示`identity_verified=true`；退出1表示身份不一致；退出2表示资料/查询无效。输出不含原始命令行、任务参数、密钥或数据库路径。通过只表示被动身份元数据相互一致，**不表示封存文件全部完好、HTTP可用、数据库健康或账实一致**。完整程序封存校验应在离线候选上用已有清单工具完成；业务验收只在本任务合成环境执行。

现有受控制品的`launch.cmd current --preflight`会进入启动预检链，不能因名称含preflight就视为无数据库访问。本计划不得对生产执行该命令，也不执行`--serve`、rollback入口、现有service_launcher的数据库/HTTP检查或默认指向8080的冒烟。不要通过取消保护标记继续。

## 生产代码切换与故障回退的审批资料

本计划只准备候选与清单，不执行以下生产动作。另行明确授权后，维护人员仍须逐项核对数据库禁令和具体操作范围；任何会触库的启动预检/启动流程都不能自动放行。

1. 记录准备发布的完整SHA、精确required CI、Android祖先和输入证明、完整制品ID/覆盖清单、依赖与解释器、原任务动作、运行入口和被动进程身份。保留完整旧制品，不在运行目录原地混入新文件。
2. 确认候选没有schema/自动迁移/回填需求；有结构变更则移出本批，单独提交设计。离线候选只使用全新合成库，通过模块、相邻、真实浏览器及完整CI。
3. 代码回退只能回到已封存、已验收且与当前数据结构兼容的完整旧程序组合；仓库Git单文件、旧依赖或某个历史界面覆盖均不足以代表完整回退制品。恢复程序不等于恢复数据库。
4. 生产停机窗口、切换和沿原任务入口启动各需具体授权。按已确认的任务与进程身份管理指定实例；不能按进程名批量结束Python或停止无关程序，也不删除任务/服务/防火墙来绕过归属检查。
5. 不把旧数据库覆盖仍在使用的业务数据；不删除数据库、旁文件、保护标记、凭据或用户目录。数据库恢复和账号操作不属于代码回退授权。
6. 获准动作完成后的生产生效证据另行记录。被动身份、人工正常使用反馈、业务健康、外部发送和硬件出纸分开验收；没有证据的项目保持待验，不能仅以监听或HTTP状态码宣布全部恢复。

## 允许的离线恢复演练

当前仅允许本任务自有lab内全新合成库；不得从生产复制数据，亦不使用未知来源的旧备份。先核对来源和目标都是无链接、无旁文件的本次合成文件，按既有隔离驱动显式放行，目标必须全新。以下是路径格式示例，不会自动创建源样本：

```powershell
$lab = 'C:\Users\Administrator\Documents\Codex\2026-11-07\wms-improvement-90\lab'
# source-synthetic.db须由本次合成夹具创建；目标fresh-restored.db此前不存在。
# 只能在已经安装数据库/网络防护的演练驱动内调用：
python scripts/restore_backup.py "$lab\restore-example\source-synthetic.db" --db "$lab\restore-example\fresh-restored.db" --yes
```

检验源/备份/恢复目标的完整性、全部模型表和多仓三账；故障拒绝前后比较目标不变，演练只代表此合成样本。实际生产恢复、停机和真实数据RTO/RPO均未验收，不能用小合成库耗时替代。

## 故障分流

| 被动结果 | 下一步 |
|---|---|
| 任务不运行或未知 | 记录状态和任务动作，核对监护回执；不自动启动或重置预算 |
| 端口归属不符/多PID | 记录归属异常，不结束占用者，不启动第二实例 |
| 后台/UI来源不符 | 保留实际完整制品，核对清单和发布记录，不原地替换文件 |
| 父链缺失/时间反转 | 视为未知或PID复用，重新取被动快照，未确认前拒绝操作 |
| 身份通过但用户报告异常 | 身份不是业务健康；先在合成环境定位，不发生产测试请求 |
| 怀疑数据问题 | 保留现场并报告；本计划禁止生产查库、备份、扫描和回填 |

软件证据、人工正常使用、AI模型、手机、打印机及持续观察的待验项分别登记。整个改善计划和前端第5项不能因本手册修订而标记完成。
